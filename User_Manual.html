System Introduction

The purpose of this system is simple: HR raises the request, IT provisions the resources, managers can see the progress, and employees complete the final acknowledgement in one traceable process. This reduces the risk of missed steps caused by verbal handovers, spreadsheets, and scattered email threads.

For HR

Employee details, onboarding assets, email groups, shared mailboxes, and approval actions are tracked in one request flow.

For IT

Checklists, software access, mailbox access, folder permissions, and signatures can all be traced back to the same request.

For Leadership

Status is easier to understand because the process shows where a request is waiting and who is responsible for the next action.

Why HR and IT Collaboration Matters

In a manual process, HR tells IT that someone is joining, and IT then has to interpret what accounts, devices, software, and access rights are actually needed. The biggest problem is inconsistency and omission. A standardized workflow fixes that by capturing requirements first and execution second, with final acknowledgement and audit visibility at the end.

Single entry point

Accounts, equipment, email groups, shared mailboxes, and folder access all start from one workflow.

Fewer missed actions

IT works through explicit steps instead of guessing what should be prepared for each employee.

Clear accountability

The system records who created, submitted, completed, and acknowledged each request.

Info
This manual focuses on the onboarding flow because it best shows the full HR-to-IT-to-employee collaboration chain.

States and Permissions

State Main operator What can be done Business meaning
Draft HR Enter employee information, save drafts, continue editing, and finally sign and submit. The request is still being prepared and has not yet been handed to IT.
HrSubmitted IT Review the submitted request and begin the IT setup steps. HR input is effectively finalized and IT can now execute the request.
ItProvisioning IT Provision software, email groups, shared mailboxes, folder access, fill the IT checklist, and complete IT sign-off. This is the execution stage where actual resource provisioning happens.
Completed Employee, HR, IT The employee reviews and acknowledges; HR and IT mainly review, resend links, and track the result. From a business point of view the work is complete, with only final acknowledgement or archive handling left.
Canceled or Rejected Authorized operator The process stops and does not continue forward. This is used when information is incorrect, the request is invalid, or the flow is intentionally stopped.

Account and Security Guide

The login journey has two related but separate security tracks: normal password-based login and OTP-based password recovery. They are not governed by the same lockout rules.

Normal sign-in

Users sign in with username or email and password. If the account is flagged for first-use password change, the system redirects to the forced change password page.

Forgot password

Users request a one-time code through their registered email address, verify the code, and then reset the password.

Recommended Understanding of the OTP Flow

1
Submit the account

The system checks whether the account exists, is active, and has a registered email address.

2
Receive the OTP

A high-strength 6-character OTP is generated and sent through the background email queue.

3
Verify the OTP

If the code is correct, the system issues a password reset token and continues to the password reset step.

Security item Rule What users should remember
OTP lifetime 5 minutes If more than 5 minutes pass, the OTP expires and a new code must be requested.
OTP failed attempts Invalidated after 3 failures This invalidates the current OTP only. It does not permanently disable the account.
OTP resend cooldown 1 minute If a code was just sent, the user should wait instead of repeatedly requesting another code.
Password login failures Account lockout after 5 failed attempts The account can be temporarily locked, and repeated lockouts increase the penalty duration.
IT alerting Lockout events can notify IT This helps the organization detect suspicious login behavior earlier.
Warning
If the user simply forgot the password, the OTP recovery path is the safest option. Repeatedly trying old passwords can trigger account lockout.
Info
From a management perspective, the most important point is that OTP brute-force protection and password login brute-force protection are handled separately. This improves security without making the account unusable because of one bad OTP session.

Frequently Asked Questions

Question Short answer
Why does the request not look fully complete right after HR submits it? Because after HR submission the request still has to move through the IT provisioning stage before the workflow reaches its complete stage.
Why does the diagram say Completed when the system sometimes shows PendingEmployeeSign? The diagram shows the higher-level business states. The stored request status is more detailed and often enters PendingEmployeeSign before the final completed status is saved.
If a shared mailbox or email group is renamed later, will old requests become unclear? No. The request stores snapshot values so historical records still show the original selected information clearly.
Does entering the OTP incorrectly three times destroy the account? No. It only invalidates that specific OTP. The user can request a new code.
